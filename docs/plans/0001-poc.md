# 0001 — Loaners proof of concept

Status: **Approved 2026-09-28** — SvelteKit (Q1); defaults accepted for Q2–Q4 and all additions.

## Goal

Prove one loop end to end in production with two real accounts:

sign up → invite a friend → add items → search friends' items → request → owner accepts → owner marks returned.

Everything else is out of scope (notifications, service worker caching, unfriending, item photos, due dates, design polish).

## Additions beyond the spec (included unless you object)

1. **`profiles` self-update.** RLS policy + column grant so a user can update only their own `display_name`. Needed for "set display name on first login". `display_name` is nullable; the signup trigger leaves it null and the app routes users with a null name to a name form.
2. **`get_invite(code)` RPC.** Returns inviter display name and whether the code is valid, so `/invite/[code]` can say "Alex invited you" before the invitee is a friend (RLS would otherwise hide the inviter's profile). Returns nothing sensitive.
3. **`/auth/confirm` route.** Server route that verifies the magic link (`verifyOtp` with `token_hash`) and sets session cookies. Requires a custom magic link email template (see Supabase Auth settings below). This works when the link is opened in a different browser than the one that requested it, which the default PKCE `?code=` flow does not.
4. **Generated types.** `supabase gen types typescript --local > src/lib/database.types.ts`, committed, regenerated after each migration.
5. **`closed_at` semantics.** Set when a loan enters any terminal state (`declined`, `cancelled`, `returned`).

### Phase 2 — Database rules

**Data model** (as specified), plus:

- `visibility` is a `text` column with a check constraint (`'friends' | 'private'`), default `'friends'`.
- `loans.owner_id` is denormalized from `items.owner_id` and set only by `request_item`.
- `items` FKs from `loans` use `on delete restrict`; the UI archives rather than deletes.
- `invites.code`: 10 random URL-safe characters, generated server-side.

**Loan state machine** (ADR 0002):

```
             respond(accept)          mark_returned
requested ───────────────────▶ active ─────────────▶ returned
    │  │
    │  └── respond(decline) / auto-decline on another accept ──▶ declined
    └───── cancel_request ──────────────────────────────────────▶ cancelled
```

Terminal: `declined`, `cancelled`, `returned`. Each transition is one RPC that locks the loan row (`for update`), checks caller and current status, then updates.

**RPCs** — all `security definer`, `set search_path = ''`, check `auth.uid()`, raise with a distinct error code/message per rule so the UI and tests can tell them apart. `execute` revoked from `public`/`anon`, granted to `authenticated`.

| Function                              | Rules                                                                                                                                                                                                                                 |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create_invite()`                     | returns code; `expires_at = now() + 7 days`                                                                                                                                                                                           |
| `get_invite(code)`                    | inviter display name, `valid` flag                                                                                                                                                                                                    |
| `accept_invite(code)`                 | code exists, not expired, not used, inviter ≠ caller; inserts `(least, greatest)` pair (no-op if already friends); marks used                                                                                                         |
| `request_item(item_id, message)`      | caller is friend of owner; item `friends`-visible, not archived, not caller's own, no active loan; unique open request enforced by index and a friendly check                                                                         |
| `respond_to_request(loan_id, accept)` | caller is owner; status `requested`; on accept: lock item, fail if another loan active, set `active`/`started_at`, decline other `requested` loans for the item                                                                       |
| `cancel_request(loan_id)`             | caller is borrower; status `requested`                                                                                                                                                                                                |
| `mark_returned(loan_id)`              | caller is owner; status `active`                                                                                                                                                                                                      |
| `search_friend_items(query)`          | friends' visible non-archived items; `available = no active loan`; ranked by `greatest(similarity(name, q), similarity(note, q))`; filtered with `%` / `ilike` so short queries still match; empty query returns all, ordered by name |

`search_friend_items` is `security definer` because availability needs the `loans` table, which friends cannot read under RLS. It filters to the caller's friends explicitly and returns only item fields, owner display name and a boolean.

**RLS** (ADR 0003):

| Table       | select                                                               | insert/update/delete                                           |
| ----------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| profiles    | self or friend                                                       | update own `display_name` only (column grant)                  |
| invites     | inviter or `used_by`                                                 | none (RPC only)                                                |
| friendships | `user_a` or `user_b`                                                 | none (RPC only)                                                |
| items       | owner: all; friend: `visibility = 'friends' and archived_at is null` | owner only; `owner_id` forced to `auth.uid()` via `with check` |
| loans       | owner or borrower                                                    | none (RPC only)                                                |

`anon` gets no table privileges.

### Phase 3 — pgTAP tests

`supabase/tests/*.test.sql`, run with `supabase test db`. A shared helper (loaded per file) creates auth users and switches role/JWT claims (`set local role authenticated; set local request.jwt.claims …`). Each file runs in a transaction and rolls back.

- `schema.test.sql`: tables, RLS enabled on every table, indexes exist, `pg_trgm` installed.
- `rls_profiles.test.sql`: self read, friend read, non-friend cannot read, cannot update another's profile, cannot change `id`.
- `rls_items.test.sql`: owner CRUD; friend sees `friends` items only; friend cannot see private or archived; non-friend sees nothing; friend cannot insert/update/delete; cannot insert with another `owner_id`.
- `rls_loans_invites_friendships.test.sql`: only involved users read; direct insert/update/delete denied for all three; anon denied.
- `rpc_invites.test.sql`: valid code, 7-day expiry, self-invite rejected, expired rejected, used rejected, unknown rejected, friendship stored ordered.
- `rpc_request.test.sql`: success; non-friend rejected; own item rejected; private rejected; archived rejected; item with active loan rejected; duplicate open request rejected; re-request after decline/cancel allowed.
- `rpc_respond.test.sql`: owner accept sets `active` + `started_at`; other open requests auto-declined; borrower cannot respond; non-requested loan rejected; double active loan rejected (including forced second accept); decline sets `closed_at`.
- `rpc_cancel_return.test.sql`: borrower cancels while requested; owner cannot cancel; cancel after accept rejected; owner marks returned; borrower cannot mark returned; returned twice rejected; item available again after return.
- `rpc_search.test.sql`: returns only friends' visible non-archived items; excludes own and non-friends' items; ranking order; empty query returns all; availability flag reflects active loan.

### Phase 4 — App

Directory layout:

```
src/
  hooks.server.ts            # create Supabase server client per request, auth guard
  app.d.ts                   # Locals: supabase, safeGetSession()
  lib/
    supabase.ts              # client helpers
    database.types.ts        # generated
  routes/
    +layout.server.ts        # session + profile; redirect to name form if display_name null
    +layout.svelte           # nav, mobile-first shell
    +page.svelte / .server.ts        # dashboard
    login/                   # email form → signInWithOtp; ?next= preserved
    welcome/                 # set display name
    auth/confirm/+server.ts  # verifyOtp(token_hash) → redirect to next
    auth/signout/+server.ts
    items/
    search/
    friends/
    invite/[code]/
static/
  manifest.webmanifest, icons (192, 512, maskable, apple-touch)
```

- All data access is server-side (`load` + form actions) using the user's session; no service role key in the app.
- Forms use SvelteKit form actions with `use:enhance`, so pages work without client JS state.
- RPC errors mapped to readable messages.
- `/invite/[code]`: unauthenticated users go to `/login?next=/invite/[code]`; after accepting, redirect to `/friends`.
- `/friends`: "Create invite link" button shows `${origin}/invite/${code}` with a copy button (`navigator.clipboard`).
- `/search`: `GET ?q=` form; Request button (with optional message) per available item; unavailable items show "On loan".
- PWA: manifest (`name`, `short_name`, `start_url: /`, `display: standalone`, theme colors), PNG icons rendered once from an SVG and committed, `<link rel="manifest">` and apple meta tags. No service worker.
