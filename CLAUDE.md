# CLAUDE.md

## Project

Loaners: a mobile-first PWA for lending items among friends. SvelteKit (Svelte 5 runes, TypeScript strict) + Tailwind v4, Supabase (Postgres, Auth with email magic links), deployed to Vercel. The POC loop: sign up → invite friend → add items → search friends' items → request → owner accepts → owner marks returned.

Decisions: `docs/adr/`. Plans: `docs/plans/`.

## Commands

```sh
npm run dev          # dev server, http://localhost:5173
npm run check        # svelte-check (strict TS)
npm run lint         # prettier --check + eslint
npm run format       # prettier --write
npm run build        # production build
npm run db:start     # local Supabase (Docker); applies migrations + seed
npm run db:reset     # rebuild local DB from migrations + seed.sql
npm run db:test      # pgTAP tests (supabase test db)
npm run db:types     # regenerate src/lib/database.types.ts
npx supabase migration new <name>
```

Before committing: `npm run db:test`, `npm run check`, `npm run lint`, `npm run build`.

## Conventions

- **Business rules live in Postgres.** Loan, invite and friendship state changes go through `security definer` RPC functions (`supabase/migrations/*_rpc.sql`). Clients never insert/update `loans`, `invites` or `friendships` directly. Only `items` (owner) and `profiles.display_name` (self) are directly writable.
- **RPC functions**: `set search_path = ''`, fully qualified names, check `auth.uid()` first, raise `P0001` with a lowercase human-readable message (the UI shows it verbatim), revoke execute from `public, anon`, grant to `authenticated`. Lock order: item row, then loan row.
- **RLS on every table.** Policy helpers go in the `private` schema (not exposed by PostgREST). Wrap `auth.uid()` as `(select auth.uid())` in policies.
- **Every policy and RPC rule has pgTAP tests**, including negative cases. Tests in `supabase/tests/*.test.sql`, each including `_helpers.psql` and running in a rolled-back transaction.
- **Migrations are append-only once pushed to the remote project.** After changing the schema, run `npm run db:types` and commit the generated types.
- **All data access is server-side** (`+page.server.ts` load/actions) using `locals.supabase`, which carries the user's session. No browser Supabase client, no service role key.
- Forms are SvelteKit form actions with `use:enhance`. Action failures return `fail(status, { error })`; use `failWith(error)` from `$lib/server/errors` for Supabase errors.
- Internal links use `resolve()` from `$app/paths` (ESLint enforces it).
- No UI component libraries or state management libraries. Plain Tailwind; shared classes (`input`, `btn`, `btn-primary`, `card`, `section-title`) are in `src/routes/layout.css`.
- Small, focused commits with imperative subject lines.
- **Never push directly to `main`.** Work on a branch and open a pull request.
- Never commit secrets. Env vars are documented in `.env.example`; `.env.local` is gitignored.

## Layout

```
docs/adr/                  architecture decision records
docs/plans/                implementation plans
src/
  app.d.ts                 App.Locals: supabase, user, profile
  app.html                 manifest + icon links
  hooks.server.ts          Supabase SSR client, session check, auth/onboarding guard
  lib/database.types.ts    generated by `npm run db:types`
  lib/server/              server-only helpers (redirect safety, error mapping)
  routes/
    +page.*                dashboard: requests, loans
    login/ welcome/        magic link sign-in, first-login display name
    auth/confirm/          exchanges the email link's PKCE code (or token hash) for a session
    auth/signout/
    items/                 own catalog
    search/                friends' items, request
    friends/               friend list, invite links
    invite/[code]/         accept invite
static/                    manifest.webmanifest, icons
supabase/
  config.toml              local stack config (auth URLs; default email templates, like hosted)
  migrations/              schema, RLS, RPC
  tests/                   pgTAP
  seed.sql                 local-only seed (alice@example.com, bob@example.com)
```
